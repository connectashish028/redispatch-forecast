# Redispatch Forecast — Schleswig-Holstein

A day-ahead probability model for **redispatch events** in the
Schleswig-Holstein Netz (SHN) distribution grid. For any of 175 substations
and any hour of the next day, the model returns the probability that the grid
operator will have to issue at least one redispatch instruction.

## What is a redispatch event?

When wind or solar farms generate more power than the local transmission lines
can move out of the region, the grid operator orders selected plants to reduce
or shift their output. Each such instruction is one redispatch event. In
Schleswig-Holstein this happens often along the windy North Sea coast.

## Setup

```bash
conda activate cvae          # or any Python 3.10+ environment
pip install -r requirements.txt
```

## End-to-end pipeline

If `data/raw/shn_operations_last_2y/*.parquet` and
`data/external/smard_weather_*.parquet` are already present, just run:

```bash
python src/build_timeseries.py    # raw -> 15-min activity matrix
python src/build_features.py      # build the hourly feature table
python src/train.py               # train + evaluate the three models
streamlit run app.py              # launch the dashboard
```

Each step writes its outputs to `data/processed/` or `models/`. Re-running a
step is idempotent.

## Using the model in code

```python
from src.predict import predict_day
df = predict_day('Husum', '2026-02-15')
# df has 24 rows: ts, town, p_1h, p_6h, p_24h
#                (and y_1h, y_6h, y_24h actuals if the date is in the cached window)
```

## What the dashboard shows

1. **Day forecast** — hour-by-hour probability curves for the next 1h / 6h /
   24h, plus a one-day summary card and a hour-by-hour table.
2. **Map** — folium map of all 175 substations, with the chosen town
   highlighted. Bubble size indicates how often each substation has had
   redispatch.
3. **What drives this prediction?** — feature attributions (TreeSHAP) for the
   peak hour of the chosen day. Plain-English labels.
4. **Model details** — test-set metrics, feature importance, methodology
   notes.

## Limitations and known issues

* **Train/serve skew (v1).** Training inputs are *actual* SMARD + weather
  values. In production they would come from a day-ahead forecast service.
  Real-world accuracy will be slightly lower (≈ 5–10% PR-AUC drop).
* **Town-centroid weather.** A single national weather series (Berlin proxy)
  is broadcast across all towns. Adequate for SH at this scale, but per-town
  fetching from Open-Meteo is a clear v2 improvement.
* **Test set is short** — three months only (Jan–Mar 2026). Re-evaluate as
  more data accumulates, especially across summer-storm seasons.
* **Scope: SHN only.** No southern German DSOs in this dataset. Coverage
  ends at the SH state border.

## Reproducibility

Everything is deterministic given:
* the same raw parquet chunks under `data/raw/shn_operations_last_2y/`,
* the same cached external file under `data/external/`,
* fixed seeds in `src/train.py` (set via `bagging_seed` if needed).

The pipeline scripts each take under a few minutes on a 16 GB laptop. A full
rebuild from scratch (timeseries → features → train) takes about 10–15 minutes.
